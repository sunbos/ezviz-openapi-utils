# Codex 主导与 Claude Code 执行

## 分工

- Codex 负责范围、架构、任务拆分、关键协议判断、验收和最终集成。
- Claude Code 按任务单完成资料整理、批量契约提取、边界清晰的实现及测试补充。
- Claude Code 的交付先视为候选结果。Codex 核对源证据、检查差异并运行必要验证后，才标记接受。

## 成本与交接

每单只提供相关材料和明确输出格式，不传整段聊天或整个原始数据集。执行模型明确固定为用户指定的 `devin/swe-2`，effort=`max`，通过 Magpie 的本地入口调用；记录接口报告的模型、token 用量及估算费用，估算不等于实际账单。

启动子进程时清除主进程继承的 Anthropic 模型、认证和路由环境变量，再加载用户 Claude Code 配置中的 Magpie 路由，并显式传入 `--model devin/swe-2`。若返回的模型标识不匹配，交付不得进入验收，不自动切换其他模型。

当前交接使用 Claude Code 的非交互模式，任务与结果落盘。它是独立的执行会话，不复用用户正在打开的交互会话。首轮契约提取禁用全部工具，仅接收已筛选、脱敏的资料并输出 JSON。

可查看的后台资料整理任务采用只读工具，最终回复JSON，由Codex审查后落盘；不关闭后台worktree隔离规则。需要写代码的后台任务应先准备受控worktree并核对工作目录与可写范围。遇到隔离拒绝，应停下修正派单配置，不能反复试写或改配置绕过。

代码任务也可以采用只读生成候选、Codex审核应用的方式，避免共享目录并发写入。长实现按小模块拆分，避免一次输出多个长文件导致流式响应截断。只恢复已经完整解析的候选片段；不猜补截断内容，编码修正与主导方补充须记录。

监控使用 `claude agents --json` 和会话记录中的公开最终回复，不整段输出终端动画或模型思考内容。完成声明、后台进程状态、候选文件和实际验证结果分别核对。

任务状态依次为 `prepared`、`running`、`submitted`、`accepted` 或 `needs_revision`。每单写明输入、可修改文件、输出、禁止操作、验收标准和未解决问题。同一文件只分配一个写入方。

## 验收

- 契约提取：检查来源身份与哈希、方法和路径、参数位置及必填性、响应与错误规则；不把猜测补成事实。
- 代码：检查真实差异及影响，执行相关回归，重点复核认证、权限、网络和设备写操作。
- 不接受删除失败测试、放宽断言或把跳过结果计作通过的交付。
- 对重复性低风险工作以机器检查为主，并抽查原文；关键协议与有副作用的行为逐项检查。

应用密钥不进入资料整理任务。真实联调由 Codex 按已有授权控制范围；写操作仍需具体任务边界与设备范围，不能运行旧版整套真实设备测试。
