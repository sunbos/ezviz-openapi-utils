# 离线契约评测与独立产品边界

## 目标与分工

把官方契约、公开SDK入口和实际发出的HTTP报文相互核对，拒绝只返回伪造成功或遗漏场景的评测。Codex负责评测边界、进程控制和独立测试；Claude Code通过Magpie固定使用devin/swe-2、effort=max，分别交付引擎H005A和案例H005B/C。

## 实施

- [x] 明确响应message/data路径及公开入口；保留官网源矛盾。
- [x] 案例使用合成值，与SDK输出独立；覆盖全部当前登记契约。
- [x] 同步/异步、各显式响应层级及四类场景，核对实际报文与请求次数。
- [x] 子进程期限、最小环境、Python网络阻断和输出抑制；父进程校验结果格、计数、输入与源码哈希。
- [x] 故障注入：错误预期、错误认证域名、无HTTP伪成功、写操作重放、伪造报告、联网、输出、死循环和源码变化。
- [x] 接入CI，说明离线证明范围，不计为真实API或模型eval成绩。

## 用户补充的独立性要求

旧utils仅供历史研究，不建立兼容shim，不以旧150项清单为验收目标。H006A删除官方登记/AST检查对旧迁移数据的依赖，保留新SDK公开入口的可达性和官方来源核验。历史表冻结到research目录；新增测试证明没有旧文件也能完成登记和离线评测。新仓库交接与旧仓库归档留到完整交付步骤，不在本地修改中假称已完成。
