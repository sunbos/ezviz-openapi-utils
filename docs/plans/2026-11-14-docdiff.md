# 文档维护的首个确定性步骤

本步骤为维护harness实现目录差异检测，不依赖LLM，独立于SDK发行包。输入两份官方门户catalog.json，输出可追溯的变化清单。输入必须先经过文档归档校验；本工具比较清单声明的hash，不冒充重新验证所有原始文件或语义兼容性。

身份为(region,doc_id)，拒绝重复身份与畸形记录。按正文content_sha256识别内容变化；raw_file_sha256、抓取时间等变化不冒充正文变化。分类为added、removed、content_changed、status_changed、source_changed、title_changed、navigation_changed；导航只忽略memberships外层顺序及完全重复项，category_path内部顺序仍有意义。

结果按身份排序，每项列出change列表、before/after的status/hash/source_url；不复制完整正文。summary统计各类数量及unchanged，needs_review只对新增、移除、正文、状态、来源变化为真；标题/导航单独变化保留记录，但不据此要求代码改动。该信号仅表示需要检查，不能据此自动发布、生成兼容承诺或降低测试。

CLI：`python -m harness.docdiff --before OLD/catalog.json --after NEW/catalog.json --output report.json`。差异并非命令失败；畸形输入退出2。禁止output覆盖任一输入（含符号链接/硬链接别名）。SDK打包仍只包含src/ezviz_unified。

验收覆盖正常变化、正文缺失与恢复、元数据噪声、导航重排、重复身份、恶意标题作为纯数据，以及真实2269项门户清单自比较无变化。SDK静态参考站点的独立清单尚未接入本步骤，不能声称所有来源均已纳入自动监控。
